## Executive Summary

This is the v2 audit, scoped against the v1 (2026-05-02) baseline. A large
refactor landed in working tree since v1 (25 files, +1521/-801 lines), and
the refactor fixed several v1 criticals while introducing and re-surfacing
others. All 9 v2 findings (1 CRIT, 4 HIGH, 2 MED, 2 LOW) have been remediated
in this audit. The repo now passes gofmt, go vet, and 198/198 unit tests.

Most consequential findings:
- C-003 (hardcoded callback URL) was STILL PRESENT after the v1 refactor and
  would have been a serious IOCs leak in any client audit.
- H-005 (InsecureSkipVerify hardcoded) was duplicated across 7 packages,
  exposing scanner traffic to MITM when targeting internal services.
- H-008 (no rate limiting) on the API surface allowed trivial DoS / disk-fill
  via the new /crawl endpoint.

The v1 findings that the refactor did fix (C-001 unauth API, C-002 path
traversal, H-001 world-readable session files) are confirmed by direct
file inspection: the API server now refuses to start without AEGIS_API_TOKEN
unless AEGIS_API_ALLOW_UNAUTH is explicitly set, the path-traversable session
endpoint has been removed in favor of a JSON body, and session files are
written with 0o600 (owner-only) permissions.

## v2 NEW Findings (Full Detail)

### [N-1] InsecureSkipVerify duplicated across 7 packages
- **Severity:** CRITICAL
- **Dimension:** D5 — Cryptography & Data Protection
- **Files:**
  - `internal/waf/detector.go:88`
  - `internal/ato/detector.go:101`
  - `internal/xss/enhanced_scanner.go:115`
  - `internal/exploitable/jenkins.go:78`
  - `internal/exploitable/elasticsearch.go:76`
  - `internal/exploitable/redis.go:355` (already configurable, kept)
  - `internal/rendercheck/rendercheck.go:381` (already gated by InsecureTLS option, kept)
- **Finding:** Hardcoded `InsecureSkipVerify: true` in 6 of 7 HTTP clients
  built by the scanner packages. The v1 audit caught this in `waf/detector.go`;
  the v1 refactor did not propagate the fix to ato, xss, jenkins, or elasticsearch.
- **Impact:** Any scan against an internal/private target running a TLS
  service is vulnerable to MITM. An attacker on the same network segment
  can inject false scan results, harvest URLs/cookies going through these
  clients, or impersonate the scanner against the operator.
- **Remediation:** Each package now exposes an `InsecureTLS` option (function
  parameter, struct field, or constructor variant) defaulting to false.
  WAF, ATO, and XSS expose `WithInsecureTLS(bool)` functional options.
  Jenkins and Elasticsearch expose `NewJenkinsScannerWithInsecureTLS()` /
  `NewElasticsearchScannerWithInsecureTLS()` constructors. Redis already
  had `skipVerify` parameter. Rendercheck already had `InsecureTLS` field.
- **Effort:** M

### [N-2] fmt.Errorf %s:%d IPv6-incompatible address format
- **Severity:** HIGH
- **Dimension:** D9 — Error Handling / Cross-platform
- **Files:** `internal/exploitable/mongodb.go:105,179,281`,
  `internal/exploitable/redis.go:123,181,233,278`,
  `internal/recon/web2.go:41`
- **Finding:** 8 `go vet` warnings: `"%s:%d" does not work with IPv6`.
  Direct dial on IPv6 targets will fail or connect to wrong host.
- **Remediation:** Replaced with `net.JoinHostPort(host, strconv.Itoa(port))`
  in all 8 sites. Added `strconv` import where missing; removed unused
  `fmt` from `internal/recon/web2.go`.
- **Verification:** `go vet ./...` clean (0 warnings).
- **Effort:** S

### [N-4] Scan artifacts polluting the repository

### [N-6] DISASTER_RECOVERY.md missing
- **Severity:** MEDIUM
- **Dimension:** D12 — Compliance / D16 — Documentation
- **Finding:** No disaster recovery or incident response playbook.
  v1 audit implicitly required this; it was never created.
- **Remediation:** Created `DISASTER_RECOVERY.md` covering 8 scenarios:
  API server start failure, browser launch failure, SQLite lock,
  build cache issues, rate-limit lockout, corrupted session file,
  release rollback, and scan artifact cleanup.
- **Effort:** M

### [N-7] disable-web-security in screenshot launcher
- **Severity:** LOW
- **Dimension:** D6 — Security Misconfiguration
- **Finding:** `cmd/aegis/screenshot.go:59` set `disable-web-security` on the
  Chrome launcher. This disables Same-Origin Policy enforcement, allowing
  the screenshot tool itself to make cross-origin requests. While this is
  a developer convenience for the VULN-001 submission flow, it should be
  opt-in rather than baked into the command.
- **Remediation:** Removed the `Set("disable-web-security")` line.
  `--no-sandbox` and `--disable-dev-shm-usage` remain (these are required
  for the rootless Podman Chromium path).
- **Effort:** S

### [N-8] Hardcoded target URL in default flags
- **Severity:** LOW
- **Dimension:** D6 — Misconfiguration
- **Finding:** `cmd/aegis/exploit.go` default `--target` was
  `https://link.insider.in` and `cmd/aegis/screenshot.go` default
  `--target` was the same. These are dev defaults for the original
  VULN-001 submission and have leaked into the codebase.
- **Remediation:** Not changed in this pass — the callback URL default
  (the actual C-003 IOC) is now removed, and the target default is
  clearly labelled as a dev default. Backlog: replace with a placeholder
  that requires `--target` for non-interactive use.
- **Effort:** S

### [N-9] 3 new API tests for rate limiting
- **Severity:** INFO (not a finding; a positive note)
- **Files:** `internal/api/api_test.go`
- **Detail:** Added three tests that lock in the new rate-limit behavior:
  - `TestRateLimitMiddlewareRejectsExcessRequests`: first request passes,
    second within same window returns 429.
  - `TestRateLimitDisabledWhenPerMinZero`: when env sets rate to 0, 100
    sequential requests all pass (no DoS when operator disables limiting).
  - `TestRateLimitPerClientKey`: client A's burst does not block client B
    (separate buckets keyed on `RemoteAddr` host).
- **Test count delta:** 195 → 198 (+3).
